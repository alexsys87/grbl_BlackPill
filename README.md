# grbl_BlackPill — grblHAL для CNC 3018 на STM32F401 / STM32F411 BlackPill

Прошивка [grblHAL](https://github.com/grblHAL/core) для настольного фрезера
CNC 3018 на плате **WeAct Studio BlackPill STM32F401CCU6 / STM32F401CEU6 /
STM32F411CEU6**. Распиновка у всех трёх одинаковая.
Драйвер платы написан **только на регистрах и CMSIS** (без HAL / LL / Cube),
проект поддерживает **IAR Embedded Workbench for ARM** и **ARM GCC на Ubuntu / WSL**. За основу взяты структура,
CMSIS, тактирование, USB CDC и проект IAR из
[Teacup_Firmware_iar](https://github.com/alexsys87/Teacup_Firmware_iar);
ядро grblHAL взято из upstream с небольшими правками для компилятора IAR
(список — в `grbl/CORE_VERSION.txt`).

В каталоге [`host`](host/README.md) — программа управления станком для
Windows (WPF, .NET 8), переделанная из Teacup Host, с возможностями Candle:
карта высот (автовыравнивание по щупу), непрерывное перемещение и
управление с клавиатуры, правка программы, недавние файлы.

**MSI для Grbl Host:** в **Actions → Windows MSI → успешный запуск → Artifacts**
доступен установщик для Windows x64 со встроенным .NET, выбором папки и иконкой
в меню «Пуск». [Инструкция](installer/README.md). Установщик не прошивает плату.

## Что есть

- ядро grblHAL (`grbl/`, версия и список правок для IAR — в `grbl/CORE_VERSION.txt`);
- 3 оси, шаговые импульсы по таймеру TIM5 (32 бит, 21 МГц), импульс
  4 мкс, задержка импульса после смены направления (`$29`);
- шпиндель: ШИМ на TIM1_CH1 (PA8, 1 кГц, 0…10000 об/мин), включение,
  направление (M3 / M4 / M5), тот же выход годится для лазера;
- СОЖ: M8 (охлаждение) и M7 (туман);
- концевики X / Y / Z, щуп (G38.2…G38.5), кнопки сброса, паузы, старта,
  датчик двери — на прерываниях EXTI с антидребезгом; **концевики можно
  отключить** настройкой `$450` — тогда их входы игнорируются и перемычки не
  нужны;
- связь с компьютером: **USB CDC** (виртуальный COM-порт на разъёме платы)
  и параллельно с ним **два UART** — USART1 и USART2, 115200, например для
  WiFi-модуля (ESP-01 с esp-link / ESP3D, мост на ESP32) или Bluetooth
  (HC-05); без USB (`USB_SERIAL_CDC 0`) основным портом становится USART1;
- настройки (`$$`), смещения и стартовые строки хранятся во **flash**
  (сектор 1, 16 КБ по адресу 0x08004000);
- команда **`$DFU`** — перезапуск в системный загрузчик STM32 для прошивки
  по USB без нажатия кнопки BOOT0;
- 84 МГц (F401) или 96 МГц (F411) от кварца 25 МГц, USB 48 МГц (если кварц
  не запустился — от HSI);
- светодиод PC13 горит, когда контроллер работает.

Размер: ~178 КБ flash, ~31 КБ ОЗУ — помещается даже в STM32F401CC (256 / 64 КБ);
у F401CE и F411CE 512 КБ flash, у F411CE 128 КБ ОЗУ.

| Сигнал | Вывод | Примечание |
|--------|-------|------------|
| X STEP / DIR | PA0 / PA1 | к драйверам (A4988, DRV8825, TMC2208 …) |
| Y STEP / DIR | **PA6 / PA7** | до версии с двумя UART были PA2 / PA3 |
| Z STEP / DIR | PA4 / PA5 | |
| ENABLE драйверов | PB0 | активный низкий (`$4`) |

| Щуп | PB15 | пластина на GND, крокодил на фрезе |
| Сброс | PB6 | кнопка на GND |
| Пауза (feed hold) | PB7 | кнопка на GND |
| Старт (cycle start) | PB8 | кнопка на GND |
| Дверь | PB9 | по умолчанию выключена |
| Шпиндель ШИМ | PA8 | TIM1_CH1, на MOSFET-модуль шпинделя / лазер |
| Шпиндель вкл. | PB1 | |
| Шпиндель направление | PB2 | |
| СОЖ охлаждение (M8) | PB4 | |
| СОЖ туман (M7) | PB5 | |
| USART1 TX / RX | PA9 / PA10 | WiFi / Bluetooth параллельно с USB; без USB — основной порт |
| USART2 TX / RX | PA2 / PA3 | WiFi / Bluetooth параллельно с USB |
| USB | PA11 / PA12 | разъём USB-C платы |
| Светодиод | PC13 | |

Выходы платы — 3,3 В: большинство драйверов шаговых двигателей и
MOSFET-модулей их понимают; для входов 5 В-логики нужен преобразователь
уровней. Входы рассчитаны на контакты на землю (внутренняя подтяжка), это
задают маски инверсии по умолчанию (`$5=7`, `$14`, `$6=1`).

Карта выводов — [`driver/boards/cnc3018_blackpill_map.h`](driver/boards/cnc3018_blackpill_map.h),
опции сборки — [`driver/my_machine.h`](driver/my_machine.h).

### Концевики: `$450`

Настройка драйвера `$450` — маска осей, на которых **установлены**
концевики (1 — X, 2 — Y, 4 — Z, 7 — все). По умолчанию `$450=0`: у
стандартного 3018 концевиков нет, входы PB12…PB14 игнорируются (не вызывают
тревог, не показываются в `Pn:` отчёта о состоянии), и подключать к ним
ничего не нужно — ни концевики, ни перемычки, при любой логике `$5`.
После установки концевиков: `$450=7` (или маска нужных осей), затем
`$21=1` (жёсткие пределы), `$22=1` (поиск нуля), `$20=1` (программные
пределы).

### WiFi / Bluetooth: USART1 и USART2

Модуль подключается к 3,3 В-выводам UART: TX модуля — к RX платы, RX модуля —
к TX платы, общий GND. Скорость 115200, 8N1 (меняется в `my_machine.h`:
`UART1_BAUD_RATE`, `UART2_BAUD_RATE`; отключение — `UART1_ENABLE 0`,
`UART2_ENABLE 0`).

USB и оба UART работают одновременно ([`driver/stream_mux.c`](driver/stream_mux.c)):

- G-код выполняется из одного порта — активного. Другой порт становится
  активным, когда он что-то прислал, а станок стоит (Idle, Alarm или режим
  проверки, планировщик пуст) и активный порт молчит 0,5 с. До этого его
  строки ждут в его буфере, отправитель ждёт `ok` как от занятого
  контроллера: ничего не теряется и не смешивается с идущим заданием;
- команды реального времени (`?` статус, `!` пауза, `~` продолжение,
  Ctrl-X сброс, отмена перемещения, коррекции) работают с любого порта:
  например, с телефона по WiFi можно поставить на паузу задание, идущее с
  компьютера по USB;
- ответы на строки (`ok`, `error:N`, вывод `$`-команд) идут в активный
  порт, а отчёты о состоянии, тревоги и сообщения — во все порты (в USB —
  если на компьютере порт открыт);
- порт, ставший активным, начинает с чистого листа: недописанная строка
  прежнего порта отбрасывается, а блокировка G-кода после ошибки (grblHAL не
  принимает G-код после `error` до пустой строки) снимается — ошибка с
  WiFi не мешает компьютеру и наоборот;
- символы, принятые UART с ошибкой кадра, отбрасываются: так отсекается
  большая часть загрузочных сообщений ESP8266 (они идут на 74880 бод).

## Настройки по умолчанию

Задаются в [`driver/cnc3018_defaults.h`](driver/cnc3018_defaults.h) (подключается
ко всем файлам опцией «Preinclude» компилятора) и применяются при первом
запуске или по `$RST=$`:

| Параметр | Значение |
|----------|----------|
| `$100…$102` шаги на мм | 800 (винт T8 шаг 2 мм, 1/8 микрошага) |
| `$110…$112` макс. скорость | 1000 / 1000 / 600 мм/мин |
| `$120…$122` ускорение | 50 мм/с² |
| `$130…$132` ход | 300 / 180 / 45 мм |
| `$0` импульс шага | 4 мкс |
| `$30` / `$31` обороты | 10000 / 0 |
| `$33` частота ШИМ | 1000 Гц |
| `$22` / `$21` / `$20` | поиск нуля, жёсткие и программные пределы выключены |
| `$450` концевики установлены | 0 — нет, входы игнорируются |

У стандартного 3018 нет концевиков: если они установлены, задайте `$450`
(см. выше) и включите `$21=1` (жёсткие пределы), `$22=1` (поиск нуля),
`$23` (направление поиска) и `$20=1` (программные пределы).

## Сборка в IAR EWARM

1. IAR Embedded Workbench for ARM 9.x.
2. Откройте `ewarm/grbl_BlackPill.eww`. В нём три проекта:
   `grbl_STM32F401CC` (256 КБ flash), `grbl_STM32F401CE` (512 КБ) и
   `grbl_STM32F411CE` (512 КБ, 128 КБ ОЗУ, 96 МГц) — выберите по маркировке
   чипа на плате.
3. Конфигурации `Debug` (оптимизация Medium) и `Release` (High, по размеру).
4. Make (F7). Результат — `ewarm/<конфигурация>/<чип>/Exe/grbl_<чип>.out` и `.bin`.

В проектах уже заданы: определения `STM32F401xC` / `STM32F401xE` / `STM32F411xE`, пути
`$PROJ_DIR$\..`, `cmsis\core`, `cmsis\device`, `driver`, Preinclude
`driver\cnc3018_defaults.h`, линкер-файлы `cmsis/linker/stm32f4*_flash.icf`
(сектор 1 flash исключён из кода — там настройки), startup из
`cmsis/startup`, `char` без знака, расширения языка IAR включены.

Файлы проектов генерирует `tools/make_ewarm.py` из шаблона, сохранённого в
IAR (`tools/ewarm_template.ewp/.ewd`). После добавления или удаления
исходников запустите `python3 tools/make_ewarm.py`.

Отладка — ST-Link (SWD: PA13 / PA14) прямо из IAR.

## Сборка прошивки GCC на Ubuntu / WSL

В Ubuntu 22.04/24.04 или Ubuntu внутри WSL установите инструменты:

```bash
sudo apt-get update
sudo apt-get install -y make gcc-arm-none-eabi libnewlib-arm-none-eabi python3
```

Из **корня репозитория**:

```bash
make -j"$(nproc)"                 # STM32F401CC, Release, USB CDC
make -j"$(nproc)" CHIP=F401E      # STM32F401CE
make -j"$(nproc)" CHIP=F411E      # STM32F411CE
make -j"$(nproc)" CHIP=F401C CONFIG=Debug
make -j"$(nproc)" all-chips       # Release для всех трёх плат
make clean                       # удалить только build/gcc
```

Результат: `build/gcc/<CHIP>/<Release|Debug>/usb/grbl.elf`, `.hex`, `.bin`
и `.map`. Выберите `CHIP` **по маркировке микроконтроллера**, не по цвету платы.
Это рабочая прошивка для физической платы: USB CDC и оба UART включены по
умолчанию, распиновка и настройки CNC 3018 — те же, что в IAR. IAR, Renode,
Windows и .NET для этой сборки не нужны. Для основного порта USART1 вместо
USB: `make CHIP=F401C USB_SERIAL_CDC=0`; результат будет в подкаталоге `uart`.
Дополнительные определения: `make EXTRA="-DUART2_ENABLE=0"`.
Для нестандартного пути компилятора: `make TOOLCHAIN_PREFIX=/opt/arm/bin/arm-none-eabi-`.

Сборка сама проверяет адрес векторов, размеры памяти выбранного чипа,
совпадение ELF/HEX/BIN и отсутствие данных HEX в секторе настроек
`0x08004000…0x08007FFF`. Heap ограничен 12 КБ, для стека зарезервированы
4 КБ, как в IAR; линкер не допускает их пересечения. В отчёте линкера RAM
может показываться как 100%, поскольку стек закреплён у верхней границы RAM;
реальные размеры секций видны в `.map` и выводе `arm-none-eabi-size`.

**Для прошивки с сохранением настроек используйте `.hex` и не включайте
полное стирание flash.** `.bin` содержит промежутки с заполнением `0xff`,
включая сектор настроек; запись BIN через DFU может сбросить настройки.

**Готовые прошивки:** Actions → **Firmware GCC (Ubuntu)** → успешный запуск →
Artifacts → `grbl-<CHIP>-<Release|Debug>-gcc`. GitHub Actions устанавливает
компилятор и собирает все три чипа в Release и Debug, без лицензии IAR.
Проверка выполняется при изменениях исходников/сборки, в pull request и
по ручному запуску. Проверки компиляции и расположения памяти не заменяют
проверку на реальной плате; перед первым движением отключите силовые выходы.

## Тестовая сборка GCC (Renode)

Тестовый Makefile в `test/gcc` остаётся отдельно и не изменён:

```
cd test/gcc
make                 # STM32F401CC, связь по USB CDC  → build_F401C_0/grbl.elf, .bin
make CHIP=F401E      # STM32F401CE
make CHIP=F411E      # STM32F411CE (96 МГц)
make TEST=1          # связь по USART1 (для эмулятора)
```

## Прошивка

- **USB DFU**: зажмите BOOT0, нажмите NRST, отпустите BOOT0 (или отправьте
  `$DFU` уже прошитой плате), затем прошейте `.hex` программой
  STM32CubeProgrammer (USB) — настройки в секторе 1 сохранятся. Можно и
  `dfu-util -a 0 -s 0x08000000:leave -D grbl.bin`, но `.bin` покрывает и
  сектор настроек: после такой прошивки они вернутся к значениям по умолчанию.
- **ST-Link**: из IAR (Download and Debug) или STM32CubeProgrammer (SWD).

После прошивки плата появляется как виртуальный COM-порт (драйвер в
Windows 10/11 встроенный). Скорость порта значения не имеет.

## Тесты в эмуляторе Renode

**Windows 10/11 x64:** запустите `test\run-renode.cmd` из корня репозитория
или `.\run-renode.cmd` из папки `test`. Скрипт сам скачает переносимые Renode,
Python, Arm GCC и GNU make, соберёт прошивки и проверит F401/F411 через USART1
и USB CDC. Устанавливать компоненты вручную, использовать WSL или подключать
плату не требуется. [Параметры и журналы запуска](test/README.md).

`test/renode/run_tests.py` запускает прошивку в [Renode](https://renode.io)
(модель STM32F401 / F411 с USB OTG FS из проекта Teacup) и проверяет по протоколу
grbl: приветствие и `$I`, `$$`, блокировку после ошибки и Ctrl-X, число
шаговых импульсов (800 на мм), направление, дугу G2, паузу и продолжение,
отмену перемещения, ШИМ шпинделя M3 / M4 / M5, СОЖ M7 / M8 / M9, запись
настройки во flash и её сохранение после перезагрузки, игнорирование
неустановленного концевика (`$450=0`) и тревогу по установленному, щуп
`[PRB:]`, кнопку паузы, работу USART2 параллельно с основным портом (статус
по `?`, выполнение команды, ожидание конца чужого задания, пауза и
продолжение задания с другого порта, ошибка на нём не блокирует основной).

```
cd test/gcc && make TEST=1 && make
python3 test/renode/run_tests.py                  # через USART1
GRBL_PORT=usb python3 test/renode/run_tests.py    # через USB CDC

cd test/gcc && make CHIP=F411E TEST=1 && make CHIP=F411E
GRBL_CHIP=F411 python3 test/renode/run_tests.py   # STM32F411 на 96 МГц
GRBL_CHIP=F411 GRBL_PORT=usb python3 test/renode/run_tests.py
```

## Структура

| Каталог | Содержимое |
|---------|------------|
| `grbl/` | ядро grblHAL (с правками для IAR, см. `CORE_VERSION.txt`) |
| `driver/` | драйвер платы на регистрах: `driver.c` (шаги, входы, EXTI, таймеры), `spindle.c` (ШИМ TIM1), `serial.c` (USART1), `usb_cdc.c` (USB OTG FS CDC), `nvs_flash.c` (настройки во flash), `ioports_aux.c` (дополнительные входы / выходы), `cpu.c` (тактирование, DFU), `main.c` |
| `driver/boards/` | карта выводов |
| `cmsis/` | CMSIS Core, файлы устройства STM32F401 / F411, startup и линкер-файлы IAR |
| `ewarm/` | проекты IAR EWARM |
| `tools/` | генератор проектов IAR |
| `Makefile`, `gcc/` | рабочая GCC-сборка прошивки для Ubuntu / WSL, startup и линкер |
| `test/gcc/` | отдельная GCC-сборка для тестов Renode |
| `test/renode/` | платформа и тесты Renode |
| `host/` | программа управления станком Grbl Host (WPF, .NET 8) |
