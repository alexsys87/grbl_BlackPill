# Grbl Host — программа управления станком CNC 3018

Программа для Windows (WPF, .NET 8) для станка с прошивкой grblHAL из этого
репозитория (и любой другой grbl 1.1 / grblHAL). Интерфейс в стиле Windows 11
(Fluent, библиотека [WPF-UI](https://github.com/lepoco/wpfui)), светлая и
тёмная тема, русский и английский язык. Сделана на основе Teacup Host из
проекта Teacup_Firmware_iar: всё, что относилось к 3D-принтеру (температуры,
экструдер, SD-карта, загрузка файлов), убрано, добавлено то, что нужно фрезеру.

Возможности:

- **подключение** по COM-порту (USB CDC платы BlackPill или USB-UART
  адаптер на USART1), **по сети через Telnet** (ESP3D, ser2net, WiFi-UART) и
  к **виртуальному станку** — симулятору grblHAL, на котором можно
  попробовать всё без железа (скорость времени ×1…×1000);
- **автоматическое переподключение**, если COM-порт пропал или оборвалась
  сеть; запрос состояния `?` каждые 200 мс, контроль связи (5 с);
- **координаты** (рабочие и машинные, `WPos = MPos − WCO`), состояние станка
  (Idle / Run / Hold / Jog / Alarm / Door / Check …), активные входы (`Pn:`),
  заполнение буферов (`Bf:`), подача и обороты (`FS:`), режимы парсера (`$G`);
- **перемещение** командами `$J=` с шагом 0,01…50 мм, по диагонали,
  остановка перемещения сразу (`0x85`); **ноль** рабочей системы по осям
  (`G10 L20 P0`), переход в ноль, **поиск нуля** `$H`, **разблокировка** `$X`,
  **мягкий сброс** Ctrl-X, пауза `!` и продолжение `~`, сон `$SLP`;
- **шпиндель** M3/M4/M5 с оборотами, **СОЖ** M7/M8/M9 (во время работы —
  переключение командами реального времени), **коррекция** подачи, холостых
  и оборотов шпинделя (`0x90…0x9D`) в любой момент;
- **щуп по Z**: `G38.2` до касания пластины, рабочий Z = толщина пластины,
  отвод на 2 мм;
- **настройки grbl** (`$$`): таблица с названиями на русском / английском и
  единицами, поиск, изменённые значения выделяются, «Записать» отправляет
  только их;
- **выполнение программы** с подсчётом символов (буфер приёма grblHAL всегда
  заполнен, размер берётся из `$I`), прогресс, прошедшее и оставшееся время,
  пауза, продолжение, **остановка без потери позиции** (пауза подачи → сброс,
  когда станок встал), остановка задания при ошибке в строке с пояснением,
  **старт с середины** с восстановлением режимов, шпинделя и СОЖ и подходом
  через безопасную высоту, **режим проверки** `$C`;
- **просмотр траектории** в 3D и сверху по уровням глубины: резание, дуги,
  врезание, подъём, щуп и холостые ходы разными цветами; рабочее поле
  станка (`$130`/`$131`) сеткой под деталью; маркер фрезы там, где станок
  находится сейчас;
- **симуляция**: траектория строится по времени (оценка по модели
  ускорений и junction deviation grbl, с настройками станка `$110…$122`,
  `$11`, `$12`), скорость ×1…×1000, шаг по перемещениям и уровням, перемотка;
  щелчок по строке листинга — симуляция до неё;
- **предупреждения** о кодах, которых grbl не знает, о выходе за рабочее
  поле, об отсутствии M3/M4;
- консоль с историей, расшифровкой `error:N` и `ALARM:N`, фильтром
  служебных строк; макросы; системы координат G54…G59; запросы `$I`, `$G`,
  `$#`, `$N`, `$PINS`, `$HELP`; переход в загрузчик `$DFU` (только эта прошивка),
  сброс настроек `$RST=$` и смещений `$RST=#`;
- **тестовая программа** для 3018 (кнопка «Тест»): карман 60 × 40 мм в
  зигзаг с чистовым проходом, круглая бобышка (G2), четыре отверстия с
  выводом стружки, линия с врезанием под углом; глубина 1,5 мм за 3 прохода,
  фреза 3,175 мм, ноль — левый нижний угол заготовки, Z0 — её верх.

## Сборка и запуск

Нужен .NET 8 SDK (Visual Studio 2022 17.8+ или `dotnet` из командной строки).

```
cd host
dotnet build GrblHost.sln -c Release
dotnet run --project GrblHost -c Release
```

Один exe-файл без установки .NET на целевом компьютере:

```
dotnet publish GrblHost -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

Тесты ядра работают и на Linux:

```
dotnet test GrblHost.Core.Tests
```

Они проверяют разбор отчёта о состоянии, разбор G-кода и построение
траектории (модальность, G91, дюймы, дуги в трёх плоскостях, G92, оценку
времени), восстановление режимов для старта с середины и протокол с
виртуальным grblHAL: подключение и чтение `$$`, выполнение тестовой
программы до конца, остановку задания при ошибке, снятие блокировки ошибки
пустой строкой, паузу / продолжение / остановку, перемещение и его отмену,
щуп и ноль, тревогу 3 при сбросе в движении, коррекцию; а также что русские
и английские строки интерфейса совпадают по ключам и аргументам.

Проект WPF собирается и на Linux (`EnableWindowsTargeting`), но запускается
только в Windows 10/11.

## Структура

| Каталог | Содержимое |
|---------|------------|
| `GrblHost.Core/GCode` | разбор блоков G-кода (`GCodeBlock`), модальное состояние и старт с середины (`ModalState`), построение траектории с оценкой времени (`ToolpathBuilder`), тестовая программа (`DemoGCode`) |
| `GrblHost.Core/Machine` | COM-порт и Telnet (`IGrblTransport`), протокол grbl с подсчётом символов и переподключением (`GrblConnection`), отчёт о состоянии (`GrblStatus`), тексты ошибок, тревог и настроек (`GrblCodes`), виртуальный станок (`VirtualGrbl`) |
| `GrblHost.Core.Tests` | тесты xUnit |
| `GrblHost/ViewModels` | состояние программы: соединение и консоль, станок, задание, просмотр |
| `GrblHost/Views` | вкладки «Задание», «Станок», «Настройки», «Сервис», листинг, консоль, просмотр |
| `GrblHost/Controls` | 3D-вид и вид по уровням глубины |
| `GrblHost/Resources` | строки ru / en (генерируются `make_strings.py` из одной таблицы), цвета тем |

Настройки программы хранятся в `%APPDATA%\GrblHost\settings.json`.

## Протокол

- После ошибки grblHAL (уровень совместимости 0) не принимает G-код до пустой
  строки: программа отправляет её сама после ошибки ручной команды. Ошибка в
  строке задания останавливает задание (пауза подачи → сброс).
- Сброс в движении grbl считает потерей позиции (тревога 3): «Стоп» задания
  сначала останавливает станок паузой подачи и сбрасывает его уже стоящим.
- Перемещения — `$J=G91 G21 X… F…`; отмена `0x85` сразу очищает и буфер
  планировщика, и буфер приёма.
