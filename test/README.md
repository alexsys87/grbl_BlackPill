# Запуск Renode-тестов на Windows

Нужны **Windows 10/11 x64**, интернет при первом запуске и свободное место для
компилятора и эмулятора. Права администратора, IAR, WSL, Python, .NET, GCC и
Renode, установленные заранее, **не нужны**. Используется штатный Windows
PowerShell 5.1. Станок подключать не нужно: прошивка работает в эмуляторе.

## Самый простой запуск

Откройте терминал в каталоге `test` и выполните:

```powershell
.\run-renode.cmd
```

Либо из корня репозитория:

```powershell
.\test\run-renode.cmd
```

Можно дважды щёлкнуть `run-renode.cmd`, но терминал удобнее: результат остаётся
на экране. Первый запуск скачивает и распаковывает компоненты и может занять
несколько минут. Последующие запуски используют локальный кэш. Важно скачать
весь репозиторий, а не только папку `test`: для сборки нужны `cmsis`, `driver`
и `grbl`.

По умолчанию собираются и запускаются **четыре конфигурации**:

- STM32F401CC / USART1;
- STM32F401CC / USB CDC;
- STM32F411CE / USART1;
- STM32F411CE / USB CDC.

Сборка выполняется существующим `test/gcc/Makefile`. Для USART1 используется
`TEST=1`, для USB CDC — `TEST=0`. Это проверка прошивки, не WPF-программы
Grbl Host; хост-приложение и IAR-проекты не изменяются, плата не прошивается.

## Отдельная конфигурация и параметры

```powershell
.\run-renode.cmd -Chip F401C -Port uart
.\run-renode.cmd -Chip F411E -Port usb
.\run-renode.cmd -Chip F401E -Port All
.\run-renode.cmd -PrepareOnly
.\run-renode.cmd -Jobs 2 -TimeoutSeconds 1200
.\run-renode.cmd -ToolsDirectory "D:\Renode tools"
```

`-Chip`: `All`, `F401C`, `F401E`, `F411E`. `All` включает F401C и F411E:
F401E отличается от F401C объёмом памяти и доступен отдельным выбором.
`-Port`: `All`, `uart`, `usb`.
`-PrepareOnly` только подготавливает инструменты, без сборки и тестов.
Лимит времени по умолчанию — 600 секунд **на одну конфигурацию**. Проверки
выполняются последовательно; `-Jobs` задаёт параллелизм компилятора.

## Какие компоненты скачиваются

| Компонент | Версия | Источник |
|---|---|---|
| Renode Windows portable, со своей средой .NET | 1.17.0 | официальный release `renode/renode` |
| Python x64 embeddable, без pip-пакетов | 3.12.10 | python.org |
| Arm GNU Toolchain, bare-metal `arm-none-eabi` | 14.3.rel1 | developer.arm.com |
| xPack Windows Build Tools: make и BusyBox sh/mkdir/rm | 4.4.1-3 | официальный release `xpack-dev-tools/windows-build-tools-xpack` |

Версии и HTTPS-адреса закреплены в `run-renode.ps1`. Для Renode, Python и
xPack проверяется SHA-256 перед распаковкой. Для Arm архив скачивается с
официального HTTPS-адреса; проверенная независимая контрольная сумма не задана.
В `.complete` каждого компонента записываются источник и SHA-256 скачанного
архива, но вычисленная после загрузки сумма Arm не подтверждает подлинность.

По умолчанию кэш находится в
`%LOCALAPPDATA%\grbl_BlackPill\renode-tools`. Компоненты не устанавливаются
системно, пользовательский PATH не изменяется. PATH дочерних процессов
подготавливается только на время запуска. Скрипт блокирует одновременное
использование одного кэша двумя экземплярами.

## Результаты

В конце выводится `All selected Renode tests passed` либо список неудавшихся
конфигураций. Если одна конфигурация не прошла, остальные всё равно проверяются.

- ELF/BIN/HEX: `test/gcc/build_<чип>_<режим>/`.
- Журналы сборки и проверок: `test/results/<чип>-<порт>/build.log`, `checks.log`.
- Полный журнал Renode и сгенерированный `.resc`: в той же папке результата.

Код возврата: `0` — всё успешно, `1` — ошибка сборки или проверки,
`2` — ошибка подготовки окружения/загрузки. Тайм-аут конкретного теста также
делает общий запуск неуспешным. В GitHub Actions workflow **Renode Windows
tests** запускает этот же CMD-скрипт и сохраняет `Renode-Windows-logs`.

## Если что-то пошло не так

- **Загрузка не удалась:** проверьте доступ к GitHub, python.org и
  developer.arm.com. Скрипт делает до трёх попыток. Для корпоративного прокси
  может потребоваться настройка доступа средствами Windows.
- **Инструмент повреждён:** удалите соответствующий каталог и ZIP из кэша,
  затем повторите запуск. Не удаляйте файлы из кэша во время работы тестов.
- **Тайм-аут на медленном ПК:** попробуйте `-Jobs 2 -TimeoutSeconds 1200` и
  смотрите полный журнал Renode.
- **Нет ELF:** сначала должна успешно пройти сборка. Запуск Python-скрипта
  сам по себе прошивку не собирает; CMD-скрипт делает оба этапа.

Для запуска непосредственно из PowerShell без CMD-обёртки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-renode.ps1 -Chip F401C -Port uart
```

`ExecutionPolicy Bypass` действует только на этот процесс; системная политика
не меняется. Ограничения доменной политики этим не обходятся.
