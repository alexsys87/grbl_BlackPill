# MSI-установщик GrblHost

## Возможности

- Windows 10/11 **x64**, установка для всех пользователей с правами администратора.
- В пакет включён .NET 8 / WPF: отдельно устанавливать .NET не требуется.
- По умолчанию: `C:\Program Files\GrblHost`; в мастере можно выбрать другую папку.
- Ярлык **Grbl Host** в меню «Пуск», значок в списке установленных приложений.
- Восстановление и удаление через настройки Windows.
- Новая версия MSI заменяет предыдущую, сохраняя выбранную папку установки.
- Установка более старой версии блокируется.
- Пользовательские настройки в `%AppData%\GrblHost` не входят в MSI и не удаляются.
- Исходный код приложения не изменяется. MSI не устанавливает USB-драйверы и не прошивает BlackPill.
Он устанавливает только Windows-приложение Grbl Host из каталога `host/`.

Пакет не подписан: сертификат подписи в репозитории не настроен. Windows может
показывать неизвестного издателя или предупреждение при скачивании. SHA-256
рядом с MSI позволяет проверить целостность, но не заменяет цифровую подпись.

## Скачать результат GitHub Actions

Откройте **Actions → Windows MSI → успешный запуск → Artifacts** и скачайте
`GrblHost-<версия>-win-x64-msi`. В архиве находятся `.msi` и `.msi.sha256`.
Отдельный `GrblHost-msi-diagnostics` содержит результаты тестов и журналы MSI.

Сборка выполняется для pull request в `main`, при push в `main` и вручную через
**Run workflow**. Автоматическая версия — `1.0.<номер запуска>`. При ручном
запуске можно указать собственную версию. Это артефакты сборки, не автоматическая
публикация GitHub Release. Для стабильного выпуска задавайте версию явно.

## Собрать локально

Нужны Windows x64, PowerShell 7 и .NET 8 SDK. WiX 5.0.2 закреплён в
`.config/dotnet-tools.json`; инструмент и расширение UI загружаются скриптом.
Для первой сборки нужен доступ к NuGet.

Из корня репозитория:

```powershell
pwsh -File installer/build-msi.ps1 -Version 1.0.0
```

Результат: `artifacts/msi/GrblHost-1.0.0-win-x64.msi` и контрольная сумма.
Скрипт очищает каталог публикации, собирает self-contained приложение без
обрезки WPF и включает все файлы среды выполнения, включая нативные библиотеки
и подпапки локализации. `THIRD-PARTY-NOTICES.md` и тексты лицензий .NET и WPF-UI также включены в пакет.

Версия MSI строго трёхчастная: `major.minor.build`, пределы `255.255.65535`.
Для обновления увеличивайте версию; четвёртое поле Windows Installer не учитывает.
Повторную сборку той же версии не следует распространять как обновление.
`UpgradeCode` в `GrblHost.wxs` должен оставаться неизменным.
При изменении базового номера версии синхронизируйте локальное значение по
умолчанию в скрипте и автоматическую версию в workflow.

## Установка без интерфейса

В командной строке администратора:

```powershell
msiexec /i GrblHost-1.0.0-win-x64.msi /qn /norestart /L*v install.log
msiexec /i GrblHost-1.0.0-win-x64.msi INSTALLFOLDER="D:\Apps\GrblHost" /qn
msiexec /fa GrblHost-1.0.0-win-x64.msi /qn /norestart
msiexec /x GrblHost-1.0.0-win-x64.msi /qn /norestart
```

Перед обновлением или удалением закройте GrblHost. Код `0` означает успех,
`3010` — успех с требованием перезагрузки. Не запускайте одновременно несколько
операций Windows Installer.

## Проверки в CI

Workflow запускает тесты ядра на .NET 8, собирает MSI и на отдельном Windows
runner проверяет:

1. Установку тестовой старой версии в нестандартную папку с пробелами.
2. Наличие и SHA-256 всех опубликованных файлов; у ярлыка проверяется путь к
   EXE-ресурсу иконки, его контрольная сумма и извлечение маленькой и большой
   иконки средствами Windows.
3. Обновление без повторного указания папки установки.
4. Запрет понижения версии.
5. Восстановление намеренно удалённой DLL.
6. Удаление приложения, ярлыка и регистрационных данных.
7. Сохранение пользовательских данных и отдельную чистую установку новой версии.

Для проверки механизма обновления используется тот же набор файлов с меньшей
версией MSI `0.0.0`; это проверка механизма обновления, а не миграции между
разными выпусками приложения. Иконка проверяется на старом и новом пакете.
Интерактивный мастер, запуск WPF-приложения и работа со станком в этой проверке
не автоматизированы; их нужно проверить отдельно перед публичным выпуском.

Скрипт `test-msi.ps1` требует администратора и явного `-AllowMachineChanges`.
Используйте его только на одноразовой тестовой машине: он действительно
устанавливает, восстанавливает и удаляет пакеты. При обнаружении существующей
установки GrblHost проверка останавливается.
